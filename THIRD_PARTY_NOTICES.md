The Audio Vivid reference encoder is fetched separately by `scripts/bootstrap.ps1`. Its sources, model and binaries are not committed to this repository. The original native CMake target builds only that encoder with its original 16-channel capacity. A Windows spelling shim for `strcasecmp` is supplied; its decoder code is neither built nor patched. The separate AC-4 build also produces an unmodified ICL Forge CLI for local verification; the portable app bundles only its streaming encoder adapter.

Cavern is fetched separately by `scripts/build-cavern.ps1` and compiled from the pinned clean checkout. Portable builds bundle its two assemblies, the original licence, and the original wrapper with a self-contained .NET runtime. The application names Cavern and links to its creator. No Truehdd binary, FFmpeg, Dolby SDK, or JOC encoder is bundled for this import path. Cavern can approximate sparse JOC reconstruction; the exporter records `sparse_workaround` in its report. Reconstructed JOC objects are not the original ADM master objects.

The Rust decoder used for independent local verification is [1254qwer/avs3a-rust](https://github.com/1254qwer/avs3a-rust), commit `59213e47a27ffa6ba9211bac1f5a6c6fd182e9d8`. It is not a runtime dependency and is not bundled.

AC-4 independent verification uses the unchanged [SakuzyPeng/MacinDecode-AC4-Core v0.1.0](https://github.com/SakuzyPeng/MacinDecode-AC4-Core/releases/tag/v0.1.0) Windows release (archive SHA-256 `8eba6d8d82d665296666d4ade4dd2e66d120efed9efdce04bf844ab4da04b04f`). It is not bundled. Its published limits (dynamic Full A-JOC assignments, at most 20 fullband upmix signals, no native bed assignments, SIMPLE timeline unsupported) inform our default compatible profile. These are decoder implementation limits, not AC-4 format limits. No decoder is modified to validate output.
